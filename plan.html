1. 개요

이키본은 "사진 속 그 나무를 그대로 받고, 받기 전에 화분·철사·사리 작업까지 주문하는" 한국형 분재 전문몰입니다. 유럽 분재몰(Bonsai Plaza)의 "나무 한 그루 = 상품 하나" 방식을 가져오고, 거기에 쿠팡처럼 옵션을 고르는 경험을 붙였습니다. 사고 나서는 "내 분재 일지"가 자동으로 생겨 물 주기·철사 제거·분갈이 시기를 알림톡으로 알려주고, 궁금한 건 장인이 답합니다. 쇼핑몰과 커뮤니티가 같은 로그인, 같은 데이터 위에 있어서 "산 나무 → 키우는 기록 → 다음 작업 주문"이 한 바퀴로 돕니다.

데모 화면 10개는 이키본 분재 — 핵심 화면 10종 데모에서 볼 수 있습니다. 화면 속 사진은 위키미디어 공용(CC 라이선스) 실제 분재 사진이고, 나무 이름·가격·치수는 예시입니다.

이 문서는 "처음 듣는 사람도 오해 없이 이해하도록" 쉬운 말로 썼습니다. 전문용어는 처음 나올 때 괄호로 풀었습니다.

2. 분재 기초 지식

분재는 "작은 나무"가 아니라 "사람이 수십 년 동안 모양을 만든 나무"입니다. 그래서 가격은 크기가 아니라 나이, 줄기 굽기, 뿌리 퍼짐, 모양의 완성도로 정해집니다. 같은 30cm 소나무가 5만 원일 수도, 200만 원일 수도 있는 이유입니다.

나무를 설명할 때 쓰는 네 가지 숫자 (시안에도 있던 항목이고, 국내 분재계에서 쓰는 말 그대로 썼습니다):

말뜻예 (문인목 해송)
수고흙 표면부터 나무 꼭대기까지 높이42cm
수폭정면에서 본 좌우 가지 끝 사이 너비36cm
목대뿌리 바로 위 줄기 굵기3.2cm
근장흙 위로 드러난 뿌리가 퍼진 너비9cm

수형(나무 모양의 종류). 직간(곳게 선 줄기), 모양목(S자로 굽은 줄기, 가장 흔함), 사간(비스듬히 기운 줄기), 현애(절벽에서 아래로 늘어진 모양), 문인목(가늘고 높게 올라간 선비풍), 쌍간(줄기 2개), 숲(여러 그루를 한 화분에). 목록 페이지의 필터가 이 기준입니다.

크기 등급. 소품(수고 20cm 이하), 중품(20~45cm), 대품(45cm 이상). 철사걸이·분갈이 공임을 이 등급별로 매깁니다. 화분도 이 등급에 맞춰 고릅니다(화분 폭은 나무 높이의 3분의 2 안팽, 깊이는 목대 굵기와 비슷하게).

수종(나무 종류) 4분류 — 시안의 분류를 그대로 썼습니다:

  • 송백류: 소나무(해송·적송·오엽송), 진백(향나무류), 주목. 사리 작업은 이 무리에만 합니다.

  • 잡목류: 단풍, 소사나무, 느티나무. 잎이 떨어져 결울 수형을 보는 재미가 있습니다.

  • 화목·실물류: 철쪽(영산홍), 매화, 모과, 애기사과. 꽃과 열매가 포인트.

  • 미니·입문: 10만 원 이하, 처음 키우는 사람용.

세 가지 작업과 "때" — 이게 사이트 설계의 핵심입니다:

작업무엇인가언제 하나사이트에 미치는 영향
분갈이흙과 화분을 갈고 뿌리를 정리소나무 2월 중순~3월, 진백 3~4월, 단풍·소사 2~3월(잎 나기 전), 철쪽 꽃 진 직후적기가 아니면 "임시 화분으로 먼저 받고 봄에 시공" 선택지를 주어야 함
철사걸이알루미늄선을 가지에 감아 모양을 잡음송백류 늦가을~결울, 잡목류 잎 떨어진 뒤몇 달 뒤 풀어야 자국이 안 남 → "철사 제거 알림"이 재방문 이유가 됨
사리·신사리는 줄기 껍질을 벗겨 흰 고목처럼, 신은 가지 끝을 그렇게 만든 것송백류만, 되돌릴 수 없음, 자연스러워지는 데 1~2년AI 그림대로 자동 진행하면 안 되고, 장인 견적을 거쳐야 함

관리 상식(배송·보증 정책에 직결). 대부분 실외수라 베란다나 마당이 필요합니다. 물은 격흙이 마르면 흔뿍, 여름엔 하루 1~2회. 한국은 여름 폭염과 결울 한파가 변수라 발송 요일(월·화)과 기간 제한이 필요합니다. 참고 사이트도 더울 때는 월요일에만 나무를 보냅니다.

참고 사이트에 없는 것이 공 우리 기회입니다: 옵션 서비스, 일지, 장인 답변, 시기 알림. 또 하나, Bonsai Plaza가 파는 나무 중 다수가 한국산이어서(상품에 "Origin: Korea", 소사나무 61cm 30년생이 995유로) 한국은 생산국인데 국내 전문 온라인몰이 거의 없다는 점입니다.

4. 핵심 화면 구성 (10개)

손님이 거치는 순서대로 1번부터 6번까지가 "사는 길", 7~9번이 "키우는 길", 10번이 우리 직원이 보는 화면입니다. 데모는 여기에 있고, 화면 속 버튼을 누르면 다음 화면으로 이어집니다.

5. 옵션 서비스 처리 방식

쿠팡에서 색상·사이즈 고르듯 보이지만, 세 옵션은 안에서 돌아가는 방식이 서로 다릅니다. 나무는 살아있고, 작업에는 "때"가 있기 때문입니다.

표. 옵션 서비스별 처리 흐름과 결제 시점
작업1단계2단계3단계결제 시점
분갈이적기 판정 (수종별 2~3월 등)적기 아니면 선택: 임시화분 / 보관 / 직접화분 + 공임 합산주문 시
철사걸이크기·수종 공임표 (소품 3만 / 중품 6만 / 대품 12만~)작업 7일 후 발송제거 시기 알림 예약주문 시
사리·신AI 예시 3안 (송백류만)장인 검토·견적 (2일 내 알림톡)고객 승인승인 후 (나무값만 먼저)

분갈이는 시기 규칙이 핵심입니다. 시스템이 오늘 날짜와 수종을 보고 "적기가 아닙니다"를 자동으로 판단해 세 가지 선택지를 보여줍니다. 기본값은 "임시 화분으로 먼저 받고, 봄에 이키본에 보내면 무료 시공"입니다. 고객은 화분을 지금 받고, 공임은 봄 예약 할인으로 0원이 됩니다. 이렇게 하면 임시 화분도 팔리고, 봄에 고객이 다시 연락해 옵니다.

철사걸이는 가장 단순합니다. 크기(소·중·대품)와 난이도(잡목 쉬움, 송백 어려움)로 공임이 정해져 있어 바로 결제합니다. 작업 기간(7일)만큼 발송이 미루어지고, 작업일에 수종별 개월 수(송백 8개월, 잡목 4개월)를 더해 "철사 제거 알림"이 자동 등록됩니다. 이 알림이 고객이 사이트로 다시 들어오는 가장 확실한 이유가 됩니다.

사리·신은 두 단계입니다. 고객이 AI 그림 3안 중 하나를 고르고 원하는 느낌을 적으면, 주문에는 "사리 요청"만 붙고 나무값만 결제됩니다. 장인이 실제 나무를 보고(살아있는 물길 위치, 껍질 상태) 가능 범위·확정 금액·기간을 2일 안에 알림톡으로 보내고, 고객이 승인하면 그때 작업비를 결제합니다. 마음에 안 들면 나무만 받습니다. 사리는 되돌릴 수 없는 작업이라 그림대로 자동 진행하면 반드시 분쟁이 납니다. AI 그림은 "방향을 정하는 도구"이지 "결과 약속"이 아닙니다. 데모 05번 화면에 이 문구가 그대로 들어가 있습니다.

사리 미리보기 그림은 나무 정면 사진을 이미지 편집 AI(사진을 주면 일부를 바꿔 그려주는 모델)에 넣어 만듭니다. 어느 모델이 사리를 가장 그럴듯하게 그리는지는 실제 나무 사진 5장으로 시험해 보고 정합니다. 데모에서는 실제 사리가 있는 다른 진백 사진을 예시로 넣었습니다.

6. 국내 환경 적용 사항

유럽 사이트와 달라지는 곳은 결제·로그인·주소·배송·법규·알림 여섯 군데뿐이고, 나머지는 그대로 씁니다. 이 여섯 개가 전체 개발 공수의 4분의 1쯤을 차지합니다.

7. 데이터 구조

표(테이블)는 엑셀 시트 하나라고 생각하면 됩니다. 쇼핑용 12개, 커뮤니티용 8개, 총 20개를 한 데이터베이스에 넣습니다. 한 군데 넣는 이유는 "산 나무가 내 일지에 자동 등록"처럼 쇼핑과 커뮤니티가 서로 참조해야 하기 때문입니다.

9. 조직 구성 (AI 에이전트 8 · 인력 2)

역할 8개 중 6개는 AI가 맡고, 분재 장인과 포장·발송은 사람이 해야 합니다. "전원 AI"로 가면 첫 분쟁에서 사업이 무너집니다. AI 에이전트는 클로드 코드에서 "서브에이전트"(각자 지시문과 도구를 가진 분신)로 파일 하나씩 정의합니다.

역할누가하는 일한계
총괄 프로듀서AI (클로드 코드 메인)대표 지시를 받아 일을 나누고 결과를 모아 보고돈·계약 결정은 대표
사이트 개발자AIMedusa 스킬로 코드 작성, Codex가 2차 리뷰운영 반영은 대표 승인 후
분재 지식 전문가AI상품 설명, 관리 가이드, 시즌 규칙, 질문 답변 초안국내 분재 서적·협회 자료를 지식 파일로 넣어야 헛소리 안 함
분재 장인사람 (파트너 분재원) + AI 보조실제 시공. AI는 견적 초안·난이도 판정·사리 미리보기·고객 설명까지이 파트너가 없으면 옵션 서비스 전체가 공중에 림
마케팅AI주간 콘텐츠 계획, 쇼츠·릴스 대본, 블로그 글, 성과 리포트발행 전 승인

운영·배송AI 반 + 사람 반AI: 발송 가능 요일 계산, 특보 보류 판단, 송장 등록, 재고 갱신. 사람: 포장하고 택배 부르기분재원이 겸하는 게 자연스러움

10. 운영 자동화 (헤르메스·마케팅)

헤르메스는 텔레그램으로 말을 걸면 클로드를 불러 일을 하는 오픈소스 비서입니다. Nous Research가 만들었고, Anthropic을 정식 지원하며, 텔레그램 봇 토큰과 클로드 API 키만 넣으면 돌아갑니다. 대표님 맥미니에 .hermes 폴더가 이미 있는 걸 보면 설치는 된 상태입니다.

표. 헤르메스 처리 경로

위쪽 갈래(운영 작업)는 바로 실행합니다. "소사나무 새 상품 등록해", "이번 주 쇼츠 3개 올려", "어제 CS 미답변 정리해" 같은 건 헤르메스가 Medusa 관리자 API와 업로드 도구를 불러 처리하고 결과를 텔레그램으로 보고합니다. 아래쪽 갈래(코드 수정)는 헤르메스가 코드를 고쳐 GitHub에 수정 제안을 올리고 → Codex가 자동 리뷰 → 시험 사이트에 반영 → 대표님이 텔레그램에서 "배포" 한 마디 → 운영 반영입니다. 이 승인 한 단계가 안전장치입니다.

비용과 주의. 헤르메스는 맥미니나 서버에 24시간 떠 있어야 하고, 클로드 API 요금은 claude.ai 구독과 별개인 종량제입니다. 에이전트 8개가 하루 종일 돌면 월 수십만 원이 될 수 있어 역할별로 모델을 나눕니다. 헤르메스는 빠르게 바뀝는 프로젝트라 업데이트 때 설정이 깨질 수 있어 "한 달에 한 번 점검"을 잡습니다.

마케팅 자동 업로드, 솤직한 현황

채널자동화 정도어떻게주의
유튜브 쇼츠완전 자동 가능공식 API. 올인 레코드에서 쓰시던 업로드 자동화 재사용없음
인스타 릴스완전 자동 가능공식 API. 비즈니스 계정 + 페이스북 페이지 연결 + 메타 앱 심사(1~2주)심사를 개발과 병행해 미리 신청
네이버 블로그기술적으로는 가능, 권하지 않음공식 글쓰기 API 없음. 브라우저를 흉내 내 자동 발행하는 프로그램은 있음(크몽에 10만~50만원대 여러 개)판매자도 "계정 정지 100% 보장 불가"라고 밝힘. 네이버는 기계 발행 대량 글을 저품질(검색 누락) 사유로 봄

네이버 블로그는 대표님 말씀대로 "완전 자동화하는 프로그램"이 실제로 팔리고 있습니다. 제가 확인한 바로는 크몽에 여러 개가 있고, 타이핑 효과·IP 바꾸기·금칙어 변환 같은 회피 기법을 넣어둡니다. 그런데 그 판매자들 스스로 "정지 100% 보장은 어렵다"고 적어 놓았고, 운영자 후기들도 "초안까지 자동, 검수와 발행은 사람"을 권합니다. 제 의견은 이렇습니다: 이키본은 네이버 검색이 가장 큰 유입 채널인데, 그 계정이 저품질에 걸리면 나머지 자동화를 다 해도 소용이 없습니다. 그래서 네이버는 "AI가 글·사진 완성본을 텔레그램으로 보내고 → 사람이 붙여넣어 예약 발행(하루 1편, 3분)"으로 가고, 정 원하시면 서브 계정 하나로 완전 자동을 시험해보는 걸 권합니다. 메인 계정은 건드리지 않는 게 맞습니다.

모든 채널 공통으로, 콘텐츠는 올리기 전에 텔레그램으로 미리보기를 받고 "승인" 후 올리는 걸 기본값으로 합니다. 전자동 발행은 틀린 수종 이름, 틀린 관리법을 그대로 내보냅니다. 승인은 하루 5분이면 됩니다.

11. 추진 일정

원래 8~9주로 잡았던 사이트를 6주로 당길 수 있고, 헤르메스와 마케팅까지 합쳤을 때 2027년 2월 초 정식 오픈이 현실적인 목표입니다. 당기는 방법은 세 가지입니다.

  1. 이 데모 화면 10개가 그대로 개발 설계서가 됩니다. 화면 설계에 드는 1~2주가 없어집니다.

  2. 한국 연동(결제·로그인·알림톡·주소)를 쇼핑몰 기본 개발과 병렬로 진행합니다. 클로드 코드 서브에이전트 2개가 동시에 일하면 됩니다.

  3. 메타(인스타) 앱 심사, 통신판매업 신고, 결제사 계약처럼 "기다리는 일"은 첫 주에 다 신청합니다.

단계기간나오는 것끝났다고 보는 기준
0. 준비10.20~10.31 (2주)프로젝트 폴더, CLAUDE.md, 에이전트 8개 정의, 분재원 파트너 계약, 결제사·알림톡·메타 신청클로드 코드가 폴더를 열면 맥락을 다 아는 상태
1. 쇼핑몰 기본11.2~11.27 (4주)홈·목록·상세·장바구니·관리자, 나무 20그루 실제 등록대표님이 휴대폰으로 나무 한 그루를 시험 주문
2. 한국 연동11.16~12.4 (3주, 1과 겹침)포트원 결제, 카카오·네이버 로그인, 알림톡, 도로명주소, 발송 요일 규칙실제 카드로 1,000원 결제→취소 성공, 알림톡 도착
3. 옵션 서비스11.30~12.18 (3주)분갈이 시기 규칙, 철사 공임표, 사리 AI(모델 시험 포함), 서비스 요청 관리 화면사리 요청→견적→승인→결제 한 바퀴가 돌아감
4. 커뮤니티12.7~12.24 (3주)일지, 게시판, Q&A, 관리 알림 자동 생성구매한 나무가 일지에 자동 등록, 알림 예약됨
— 비공개 시험1.4지인 10명이 실제 구매고사·파손 없이 배송 완료
5. 헤르메스1.4~1.15 (2주)텔레그램 연결, 운영 작업 모드, 코드 수정 승인 흐름텔레그램에서 "상품 등록해"가 돌아감
6. 마케팅 자동화1.11~1.29 (3주)쇼츠·릴스 자동 업로드, 네이버 반자동, 주간 콘텐츠 계획승인 한 번으로 세 채널에 나감
— 정식 오픈2.1

단계마다 "끝났다고 보는 기준"이 있어서, 각 단계가 끝날 때마다 실제로 쓸 수 있는 게 하나씩 생깁니다. 셀을 동시에 시작하면 어느 것도 완성이 안 된 채 4개월이 갑니다. 분갈이 적기가 2~3월이라 2월 초 오픈이 "봄 분갈이 예약" 영업에 딱 맞는 타이밍입니다.

12. 결정 사항 · 위험 · 의견

정해야 할 것 네 가지:

  • 분재원 파트너 — 누가 나무를 대고 시공하는가. 이게 없으면 옵션 서비스 전체가 없는 것과 같습니다.

  • 결제 중계사 — 포트원(간편결제 다 포함) vs 토스페이먼츠(단순). 제 추천은 포트원.

  • 서버 위치 — 국내(네이버클라우드·AWS 서울) vs 해외 PaaS. 국내 고객만 상대하므로 국내.

  • 헤르메스 권한 — 운영 작업만 vs 코드 수정까지. 코드는 승인 절차를 두자는 게 제 의견.

솔직한 반대 의견 세 가지:

첫째, "모든 인력을 AI로 대체"는 반대입니다. 사리를 깎고 나무를 포장하는 건 손으로 하는 일이고, 환불 분쟁은 사람이 막아야 합니다. AI 8 + 사람 2가 현실적인 최소 구성입니다.

둘째, 사리 AI를 처음부터 자동 결제로 가면 안 됩니다. 되돌릴 수 없는 작업을 사진만 보고 약속하면 첫 사고에서 신뢰가 끝납니다. "AI 컴셉 → 장인 견적" 2단계가 안전하고, 오히려 상담이 들어오니 영업 접점도 됩니다.

셋째, 네이버 블로그 완전 자동화는 기술적으로 되지만 메인 계정에는 쓰지 말자는 게 제 의견입니다. 이유는 위 마케팅 표에 있습니다. 대표님 생각과 다른 부분이니 서브 계정으로 시험해보고 결정하셔도 됩니다.

의미: 이 틀대로 가면 국내에 없는 "옵션 서비스가 붙은 분재 전문몰 + 일지 커뮤니티"가 2월 초에 나옵니다. 차별점 3개(사진 그대로 + 시기 맞춘 분갈이 + 사리 상담) 중 가장 돈이 되는 건 분갈이·철사걸이 공임의 반복 매출일 가능성이 높고, 사리 AI는 사람을 불러오는 간판 역할입니다.
